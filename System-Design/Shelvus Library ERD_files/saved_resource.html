Generalisation of User

Borrower and Librarian share everything in User and add only what's specific to them. The user_type attribute records which subtype each user belongs to.

  • DisjointA user is a Borrower or a Librarian, never both. The d in the circle marks this.
  • TotalEvery user must be one of the two. There's no plain User without a subtype. The double line from User marks this.
  • Shared keyEach subtype uses the same user_id as its User row, as both its primary key and a foreign key. That's why the ERD shows a one-to-zero-or-one line between User and each subtype.

Borrowing rules

  • Associative entityBorrowing resolves the many-to-many relationship between Borrower and Book. Each row is one loan, with its own borrowing_id, so the same borrower can borrow the same book again later and the history is kept.
  • Only Borrowers borrowBorrowing links to Borrower, not to User, so a Librarian account can't take out a loan.
  • Issued byA Librarian may issue many loans. A loan doesn't need one (for self-service), so this side is zero or one.
  • One active loan per bookA book can only appear in one Borrowing with no return_date at a time.
  • Loan limitA borrower's active loans can't go over their max_loans.
